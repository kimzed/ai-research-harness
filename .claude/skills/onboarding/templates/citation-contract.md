> **You are reading the template**, at
> `.claude/skills/onboarding/templates/citation-contract.md`. It is mechanism:

> this harness, and it holds **no project's decisions**. Nothing here has been

> you opened.
>

> from this template by the `onboarding` skill and filled in with what the

> reading decisions out of this template.

**Instruction to the generator (the `onboarding` skill), not content to copy:**
when writing the repo-root `citation-contract.md`, replace the H1 and the
blockquote above with the header block below, verbatim, and drop this
instruction paragraph. The two files must stay distinguishable both to a human
who opens one of them and to a repo-wide grep -- a generated contract that
still claims to be the template, or a template that claims to be a contract, is
the exact confusion this block exists to prevent.

Every decision in this contract is *asked*, never assumed. The tables and
formats below arrive from the template as **starting proposals**. A proposal
becomes a decision only when the researcher has confirmed it in conversation --
at which point that section's own `_not-yet-negotiated_` marker is replaced
with the actual decision (and, where useful, its rationale and the date it was
agreed).

---

## 1. Citation style

**Negotiated decision:** _not-yet-negotiated_

Ask the researcher which biblatex style fits their target venue or thesis
style guide -- e.g. `numeric` (biblatex's own implicit default if `style=` is
left unset), `authoryear`, `apa`, or a journal-specific `.bbx`. Their answer to
the project's target-output/venue question is the natural input here, but it is
not a substitute for asking.

Do **not** default silently to `numeric` by omission -- an explicit, recorded
choice is the entire point of this section. Once decided:

- set it in `manuscript/main.tex`'s
  `\usepackage[backend=biber,style=<decided>]{biblatex}`, and
- record the choice (and why) above, replacing the placeholder.

## 2. Zotero collection root (AD-2)

**Negotiated decision:** _not-yet-negotiated_

AD-2: each project instance names its own collection root; filing and Better
BibTeX's export scope stay inside that collection, never library-wide, so one
shared Zotero library can serve several project repos without their references
bleeding into each other.

Use `zotero-code-execution`'s `--check-target` to see which library/collection
filing would land in right now, and to list the available targets, then ask the
researcher which collection is this project's root (or whether they want to
create a new one in Zotero's own UI first).

If Zotero desktop is not reachable when this is negotiated, leave this section
unfilled and flagged rather than guessing a collection -- an unreachable Zotero
is not a decision.

## 3. Field completeness checklist per reference type

**Each reference type below carries its own `Negotiated decision:` marker, and
they are settled independently.** "`@article` agreed, `@thesis` still open" is a
normal, expressible state -- so the HALT rule keys off *the marker on the table
for the type in front of you*, not off this section as a whole. An item whose
own type is still marked `_not-yet-negotiated_` HALTs even when every other
table has been agreed.

Refine the Required/Recommended/Optional splits with the researcher one type at
a time, and replace only that type's marker as it is confirmed.

Field names below are Better BibTeX's biblatex-flavored export names (e.g.
`journaltitle`/`date`, not classic BibTeX's `journal`/`year`).

Only `@article`, `@inproceedings`, `@book`, and `@thesis` have proposal tables.
If the researcher's library has (or is expected to have) other Zotero item
types -- web pages, software, datasets, preprints, reports, book chapters --
negotiate a checklist for those too and add a table (with its own marker) here,
rather than leaving them unchecked.

## 4. Malformed-field format

**Negotiated decision:** _not-yet-negotiated_ -- proposal below; confirm the
date format fits the researcher's field/venue before treating it as decided.

`date` (and `urldate`) as a partial-or-full ISO 8601 date -- `YYYY`, `YYYY-MM`,
or `YYYY-MM-DD`. A natural-language date (`"April 2003"`, `"Spring 2003"`,
`"n.d."`) is malformed under this proposal: flag the specific field and the
expected format rather than silently reformatting or guessing.

---

## Standing rule: an uncovered type or field is a question, never a guess

This rule is **not** negotiable and stays true whatever the sections above end
up saying.

When an item is being filed, read, or cited and this contract has no row for
its reference type (a dataset, a preprint, a report, a web page, software...),
or the item has a field this contract does not yet speak to:

- **HALT.** Do not silently pass the item through, and do not silently block it
  either.
- **Ask the researcher** for that type's checklist (or that field's
  requirement), the same way the sections above were negotiated.
- **Append the answer to this file**, as a new table or a new row, so the next
  item of that type resolves without re-asking.
- **Never** invent a rule, infer one from a neighbouring type, or fill a gap
  with a plausible-looking default. A gap in this contract is a conversation to
  have, not a blank to fill in.

The same applies to this file as a whole: if a section still reads
`_not-yet-negotiated_` when a citation is needed, HALT and point the researcher
at the `onboarding` skill.

Detection and remediation behavior -- how a missing Required field is chased
down (external-lookup chain, Ask First on any recovered value, per-item accepted
gaps, never writing into `references.bib`) -- is fixed mechanism, not a
per-project preference, and lives in `.claude/skills/zotero-code-execution/SKILL.md`
under "Field-completeness check". It is deliberately not repeated here.
