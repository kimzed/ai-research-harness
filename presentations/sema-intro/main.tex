\section{The problem you don't have yet}

\begin{frame}
\frametitle{Year one of a PhD: a preview}
\begin{minipage}{\textwidth}
\begin{columns}
\begin{column}{0.58\textwidth}
\begin{itemize}
    \item 47 PDFs in \texttt{Downloads/}, all named
          \texttt{s41586-024-07123-4.pdf}
    \item A citation key you typed by hand at 2am. It was wrong.
          \texttt{biber} knew. \texttt{biber} said nothing useful.
    \item A number in your draft, and nobody -- including you -- is
          entirely sure which version of the script produced it
    \item Five separate tools, and \emph{you} are the glue between them
\end{itemize}
\end{column}
\begin{column}{0.42\textwidth}
\begin{block}{The actual cost}
None of the individual steps are hard. The cost is the constant hand-off
between them -- and every hand-off is a place to lose time, introduce a
wrong number, or use a stale citation key.
\end{block}
\end{column}
\end{columns}
\end{minipage}
\end{frame}

\begin{frame}
\frametitle{``But I already have ChatGPT''}
A general chat AI can discuss a paper and draft a paragraph. It also
\alert{has no hands}:
\begin{itemize}
    \item it cannot open the actual PDF sitting in your actual folder
    \item it cannot run the actual analysis script on your actual data
    \item it cannot write into the actual \texttt{.tex} file
    \item it cannot touch the actual Zotero library
\end{itemize}
\vspace{2mm}
So you still do all of the moving. You are a very expensive USB cable.
\vspace{2mm}
\begin{block}{This one has hands}
Slightly alarming. Extremely useful. It opens the files, runs the scripts,
files the papers, writes the numbers, and compiles the PDF -- inside one
continuous conversation, with every step recorded.
\end{block}
\end{frame}

\section{The crew}

\begin{frame}
\frametitle{Zotero (+ Better BibTeX): the one true library}
\begin{columns}
\begin{column}{0.6\textwidth}
\begin{itemize}
    \item Your reference library is the \emph{single system of record}.
          Nothing gets re-typed anywhere else.
    \item Claude Code acts as a \emph{second user of your library}: it
          files into the collections you already made, and never invents
          its own folder structure.
    \item Better BibTeX owns the citation keys and keeps
          \texttt{references.bib} exported automatically.
    \item Claude Code only ever \emph{reads} that file.
\end{itemize}
\end{column}
\begin{column}{0.4\textwidth}
\begin{figure}
\includegraphics[width=4.2cm]{zotero.png}
\end{figure}
\end{column}
\end{columns}
\vspace{1mm}
\begin{block}{House rule number one}
It has never once written \texttt{smith2019a?} and hoped. If the paper
isn't filed yet, it tells you so instead of guessing a key.
\end{block}
\end{frame}

\begin{frame}
\frametitle{LaTeX / TeX Live: the writing surface}
\begin{columns}
\begin{column}{0.6\textwidth}
\begin{itemize}
    \item TeX Live compiles the document. Claude Code runs the build loop
          and gets back a \emph{structured} list of problems -- file,
          line, package, message -- instead of 4000 lines of log.
    \item You keep a normal human window: VS Code with LaTeX Workshop,
          PDF preview on the right, click the PDF to jump to the source
          line.
    \item That editor is deliberately \emph{not} automated away. It reads
          the same git-tracked files.
\end{itemize}
\end{column}

\begin{frame}
\frametitle{Obsidian: where understanding goes to survive}
\begin{columns}
\begin{column}{0.62\textwidth}
\begin{itemize}
    \item \texttt{knowledge-base/} is a plain-markdown vault on your own
          disk. No cloud, no lock-in, no database.
    \item When you and Claude Code finish arguing about a paper, the
          understanding does not evaporate with the chat window: it

    \item \texttt{[[Wikilinks]]} between notes, graph view for free.
    \item No folder scheme imposed upfront -- the structure emerges from

\begin{frame}
\frametitle{Semantic Scholar + OpenAlex: the literature radar}
\begin{columns}
\begin{column}{0.6\textwidth}
\begin{itemize}
    \item ``Find me papers like this one'' $\rightarrow$ Semantic

\begin{frame}
\frametitle{Git: an undo button for your thesis}
\begin{columns}
\begin{column}{0.62\textwidth}
\begin{itemize}
    \item Every edit is committed, scoped to exactly the files touched in

    \item The design goal, word for word: \emph{any single writing or

\section{A day with it}

\begin{frame}
\frametitle{What it actually looks like}
\begin{block}{You}
``Find papers similar to the one I cited in the introduction.''
\end{block}
\textbf{It} searches Semantic Scholar, cross-checks OpenAlex, and shows
you the candidates -- titles, years, abstracts -- in the conversation.
\begin{block}{You}
``Numbers 2, 5 and 7 look right.''
\end{block}
\textbf{It} checks your Zotero library for duplicates, files the three
into your collection, and hands back the pinned citation keys.
\begin{block}{You}
``Use number 5 in the related-work paragraph.''
\end{block}
\textbf{It} re-reads the live bibliography, writes the citation,
recompiles, and reports zero undefined references.
\vspace{2mm}
No manual Zotero clicking. No copy-paste. One conversation.
\end{frame}

\section{The fine print}

\begin{frame}
\frametitle{Things it is not allowed to do}
\begin{itemize}
    \item Invent a citation key. Ever. Not even a very plausible one.
    \item Fabricate a number, a table, or a figure -- if the script
          didn't produce it, it does not go on the page.
    \item Overwrite something you wrote without asking first.
    \item Hand you a generated result without saying which script and
          which commit made it.
\end{itemize}
\vspace{2mm}
Written into the spec as an explicit rule not to optimise around:
\emph{a wrong number silently inserted is worse than one that requires a
manual check.}
\begin{block}{The important part}
This is an assistant, not an autopilot. You are still the last check
before anything counts as true. It just removes the twelve boring steps
between having an idea and seeing whether it holds.
\end{block}
\end{frame}

\begin{frame}

    \item So: one real task. A messy folder of PDFs, a related-work

\end{itemize}
